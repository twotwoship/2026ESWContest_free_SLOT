# UART RESULT R=2 오판 문제 트러블슈팅

설계 타임라인

| 단계 | 구조 | 발생 문제 | 감지율 |
|---|---|---|---|
| 1차 | ATmega가 `RESULT|요청번호|XYR`로 배출 결과 전송. Pi는 `R=1` 성공, `R=0` 미감지 실패, `R=2` 빈 슬롯으로 처리 | 첫 번째 약은 정상 배출 및 성공 처리됨. 두 번째 약은 실제로 나왔으나 ATmega가 `R=2`를 전송하여 Pi가 빈 슬롯으로 판단 | 1/2 |
| 2차 | Pi 로그 및 DB 이벤트 확인 | `RESULT|0000003D|012` 수신 직후 `EMPTY_BLISTER_SLOT` 이벤트 기록. Pi는 명세대로 다음 좌표 `(0,2)`로 이동 | 오판 원인 확인 |
| 3차 | ATmega 판정 로직 점검 필요 | 실제 배출 여부와 빈 슬롯 여부가 분리되지 않아, 약이 나온 상황에서도 빈 슬롯 코드가 발생할 가능성 확인 | 펌웨어 수정 필요 |
| 4차(최종) | `R=2` 조건 강화 + 배출구 IR 감지 시간 보정 + Pi 확인/보호 로직 추가 | 실제 배출된 약을 빈 슬롯으로 처리하여 다음 약까지 배출하는 문제 방지 | 목표 20/20 |

○ 문제 1 : 실제 약 배출 후 `R=2` 빈 슬롯으로 오판
- 원인: ATmega가 두 번째 슬롯 `(0,1)` 배출 후 `RESULT|0000003D|012`를 전송함. `012`는 `X=0`, `Y=1`, `R=2`이며, 현재 명세에서 `R=2`는 “압출기는 정상 동작했으나 해당 블리스터 슬롯이 비어 있음”을 의미한다. 따라서 Pi는 약이 실제로 나왔는지 다시 판단하지 않고 빈 슬롯으로 처리함
- 해결: ATmega 펌웨어에서 `R=2` 발생 조건을 강화한다. 별도의 빈 슬롯 검출 근거가 확실할 때만 `R=2`를 보내고, 배출구 IR 센서 미감지만으로는 `R=0`을 보내도록 분리한다

○ 문제 2 : Pi가 `R=2` 수신 시 자동으로 다음 슬롯으로 이동
- 원인: Pi 로직은 `R=2`를 정상적인 빈 슬롯 신호로 보고 `continue_after_empty_slot()`을 실행한다. 이 함수는 현재 좌표를 `EMPTY_BLISTER_SLOT`로 기록한 뒤 같은 복약 건을 다음 좌표로 이동시킨다
- 해결: 안전성을 위해 `R=2` 수신 시 즉시 다음 슬롯으로 이동하지 않고, LCD에 “약이 나왔나요?” 확인 화면을 띄우는 보호 로직을 추가한다. 사용자가 “나왔음”을 누르면 현재 복약을 완료 처리하고, “안 나왔음/빈칸”을 누를 때만 다음 슬롯으로 이동한다

○ 문제 3 : 배출구 IR 센서 감지 타이밍 부족 가능성
- 원인: 약이 고속으로 떨어지거나 튕기면 센서 광축을 짧게 지나가며, ATmega의 판정 창이 짧을 경우 배출을 놓칠 수 있다. 이때 펌웨어가 미감지를 빈 슬롯으로 연결하면 실제 배출 후에도 `R=2`가 발생한다
- 해결: 서보 동작 직후부터 일정 시간 동안 IR 센서를 폴링하고, 감지 신호를 래치한다. 순간 감지라도 한 번 들어오면 `R=1`로 확정하며, 판정 창은 약 낙하 완료 시간보다 충분히 길게 설정한다

○ 문제 4: 중복 `DISPENSE` 송신으로 인한 상태 혼선 가능성
[현상]
- 두 번째 배출에서 같은 초에 `DISPENSE|0000003D|0|1`이 두 번 송신되었고, ATmega도 `ACK|0000003D|DISPENSE`를 두 번 전송했다
- 이후 약은 실제로 나온 것으로 보이나, 최종 결과는 `RESULT|0000003D|012`로 들어왔고 Pi는 `EMPTY_BLISTER_SLOT`로 기록했다

[추정 원인]
- Pi 쪽 재전송 또는 버튼 중복 입력으로 같은 DISPENSE 요청이 짧은 시간에 두 번 나갔을 가능성이 있다
- ATmega가 같은 요청번호의 중복 DISPENSE를 받았을 때 서보를 재구동하지 않고 ACK만 재전송해야 하지만, 펌웨어 상태 처리에 따라 내부 판정 타이밍이 꼬일 수 있다
- 다만 이번 오판의 직접 원인은 중복 송신 자체가 아니라 ATmega가 `R=2` 결과를 보낸 것이다

[해결 방법]
- ATmega 펌웨어에서 같은 DISPENSE 요청번호가 이미 `DISPENSING` 또는 `RESULT_READY` 상태이면 서보를 다시 움직이지 않고 저장된 ACK 또는 RESULT만 재전송하도록 한다
- Pi 쪽 LCD 버튼은 한 번 누른 뒤 즉시 비활성화하고, 서버에서도 같은 schedule이 이미 `DISPENSING`이면 추가 DISPENSE 요청을 무시하도록 한다
- `R=2`는 배출구 IR 미감지와 동일하게 사용하지 않는다. 빈 슬롯을 판정하려면 별도 조건을 둔다
  - 압출 전 슬롯 확인 센서가 있는 경우: 슬롯 내 약 없음이 확인될 때만 `R=2`
  - 별도 빈 슬롯 센서가 없는 경우: 기본값은 `R=0`, 필요 시 Pi에서 사용자 확인 후 다음 슬롯 진행
- IR 감지 로직은 다음 순서로 정리한다
  - 서보 시작 직전 센서 기준값 측정
  - 서보 동작 중 및 동작 후 1~2초 동안 짧은 주기로 감지
  - 한 번이라도 차단 감지 시 `R=1`로 래치
  - 판정 시간 종료까지 감지 없으면 `R=0`
  - 별도 빈 슬롯 검출 근거가 있을 때만 `R=2`

[결과]
실제 약이 배출되었는데도 빈 슬롯으로 처리되어 다음 약으로 넘어가는 문제를 방지할 수 있다. 최종 목표는 동일 조건 20회 반복 테스트에서 `R=1` 성공 처리 20/20을 달성하는 것이다
