# 약SLOT-GUARD 4인치 터치 LCD UI/UX 기획서

문서 버전: v0.4
작성 기준일: 2026-08-24  
대상 장치: Raspberry Pi 4 Model B Rev 1.5 + Waveshare 4inch RPi LCD (A) Rev 2.0 + ATmega128A  
LCD 기준: 480×320 가로형, XPT2046/ADS7846 호환 저항막 단일 터치  
소프트웨어 기준: Raspberry Pi OS 64-bit, Debian 13 Trixie, Flask/Chromium 키오스크

## 1. 문서 목적

이 문서는 약SLOT-GUARD의 4인치 LCD가 담당하는 사용자 안내, 복약 배출 제어, 장치 상태, 음성·블리스터·전원 설정과 Raspberry Pi–ATmega128A 간 상태 흐름을 정의한다.

LCD에서는 복약 예약을 등록·수정·삭제하지 않는다. 예약 관리는 관리자 인증이 적용된 스마트폰/PC 로컬 웹에서만 수행한다.

## 7. 상태 모델

```text
SCHEDULED
  └─ 예약 도달 → MOVING
       └─ MOVE ACK + 위치 도착 WAIT → READY_TO_DISPENSE
            └─ 사용자가 약 배출 터치 → DISPENSING
                 ├─ XYR의 R=1 → DISPENSED
                 ├─ XYR의 R=0 → FAILED
                      ├─ 직접 복용 확인 → MANUALLY_COMPLETED
                      └─ 복용하지 못함 → FAILED 확인 처리
                 └─ XYR의 R=2 → 빈 슬롯 기록·다음 좌표
                      ├─ 다음 슬롯 → MOVING → WAIT → 약 배출 재선택
                      └─ 마지막 슬롯 → 블리스터 교체·초기화
                           ├─ 수동복약 → MANUALLY_COMPLETED, 00→01
                           └─ 수동미복약 → MOVING(00) 또는 만료 시 MISSED

READY_TO_DISPENSE에서 허용시간 종료 → MISSED
MOVING/DISPENSING에서 통신 응답 종료 → COMM_ERROR
```

### 7.1 상태의 의미

| 상태 | 의미 | 슬롯 이동 |
|---|---|---|
| SCHEDULED | 미래 예약 | 없음 |
| MOVING | MOVE 명령 후 위치 이동 또는 ACK 대기 | 없음 |
| READY_TO_DISPENSE | 위치 도착, 약 배출 버튼 활성 | 없음 |
| DISPENSING | DISPENSE 명령 후 서보·센서 결과 대기 | 없음 |
| DISPENSED | 센서가 배출구 통과를 감지 | 다음 슬롯 |
| FAILED | 서보 동작 후 센서 감지 실패 | 없음 |
| MANUALLY_COMPLETED | 사용자가 직접 복용했다고 확인 | 다음 슬롯 |
| MISSED | 허용시간 안에 배출 버튼을 누르지 않음 | 없음 |
| COMM_ERROR | ACK, WAIT 또는 RESULT가 허용시간까지 없음 | 없음 |

`DISPENSED`는 정제의 배출구 통과를 의미하며 실제 삼킴을 증명하지 않는다. `MANUALLY_COMPLETED`는 사용자의 자기 확인 기록이며 센서 검증 결과가 아니다.

## 8. UART v2 요약

```text
Pi → AT: MOVE|00000001|0|0|003600
AT → Pi: ACK|00000001|MOVE
AT → Pi: WAIT|00000001

Pi → AT: DISPENSE|00000002|0|0
AT → Pi: ACK|00000002|DISPENSE
AT → Pi: RESULT|00000002|001
Pi → AT: ACK|00000002|RESULT
```

- 요청번호는 8자리 대문자 16진수이다.
- MOVE와 DISPENSE는 서로 다른 요청번호를 사용한다.
- 재전송은 최초 요청번호와 전체 데이터를 그대로 사용한다.
- AT의 `ERROR|INVALID_FORMAT`에는 요청번호가 없으며, Pi는 마지막 송신 프레임 전체를 그대로 재전송한다.
- ATmega는 같은 요청번호를 다시 받아도 모터를 다시 구동하지 않는다.
- 결과의 마지막 3자리는 기존 XYR이다.
- R은 `0` 실패, `1` 배출 확인, `2` 빈 블리스터 슬롯이다.
- R=2 뒤에는 새 요청번호와 현재 남은 허용시간으로 다음 좌표 MOVE를 보낸다.
- 세부 규격은 `ATmega128A_UART_구현명세_v1.0.md`를 따른다.

## 10. 블리스터 정책

1. 슬롯은 화면의 1~10번과 내부 좌표 `00, 01, 02, 03, 04, 14, 13, 12, 11, 10`을 순서대로 대응한다.
2. DISPENSED, R=2 빈 슬롯 또는 MANUALLY_COMPLETED에서 다음 슬롯으로 이동한다.
3. R=0의 FAILED, MISSED, COMM_ERROR에서는 현재 슬롯을 유지한다.
4. 10번째 슬롯 완료 후 자동으로 1번으로 돌아가지 않는다.
5. `새 블리스터 초기화`가 완료될 때까지 신규 MOVE 명령을 차단한다.
6. LCD 초기화는 현재 슬롯과 사용 표시만 초기화하고 미래 예약은 유지한다.
7. 진행 중인 MOVING/READY_TO_DISPENSE/DISPENSING 상태에서는 초기화를 금지한다.
8. 마지막 슬롯 R=2 후 초기화하면 좌표 00에서 대형 `수동복약`·`수동미복약` 버튼을 표시한다.
9. 수동복약은 MANUALLY_COMPLETED와 좌표 01로 종료한다.
10. 수동미복약은 남은 허용시간으로 좌표 00 MOVE를 보내고 WAIT 후 기존 약 배출 버튼을 표시한다. 허용시간이 끝났으면 MOVE 없이 MISSED로 종료한다.
11. 마지막 슬롯 10의 R=1 RESULT ACK 후 ATmega는 물리 위치를 00으로 자동 복귀하며, LCD는 블리스터 소진 안내를 유지한다.
12. AT의 INVALID_FORMAT은 동일 UART 명령 재전송으로 처리하므로 LCD를 통신 오류 화면으로 전환하지 않는다.
13. 업그레이드 시 사용 중인 기존 블리스터는 기존 순서를 유지하고, 새 블리스터 초기화 이후 지그재그 순서를 적용한다.

## 11. 음성 정책

- 기본 반복 1회, 설정 범위 0~10회
- 반복 0회에서는 모든 자동 안내 음성을 재생하지 않고 장치 상태에 `미사용`을 빨간색으로 표시
- 음성 파일 재생 종료 후 5초 간격
- 사용자가 약 배출 버튼을 누르면 진행 중·대기 중 반복 재생 중단
- 볼륨 크기: `− / 현재 값 / ＋` 방식, 0~10 범위
- 1~9는 숫자만 표시하고, 0은 `음소거`, 10은 `최대`로 표시
- 기본값은 5
- `볼륨 테스트`는 현재 볼륨으로 복약 안내 음성을 1회만 재생
- 0에서 테스트하면 음소거 상태임을 표시하고 재생하지 않음
- 야간에도 같은 설정 적용
- 설정값은 SQLite에 저장하여 재부팅 후 유지

## 12. 오류 정책

| 오류코드 | 조건 | LCD 처리 |
|---|---|---|
| MOVE_ACK_TIMEOUT | MOVE ACK 미수신 | COMM_ERROR 유지 |
| MOVE_READY_TIMEOUT | MOVE ACK 후 WAIT 미수신 | COMM_ERROR 유지 |
| DOSE_BUTTON_TIMEOUT | WAIT 후 배출 버튼 미터치 | MISSED 유지 |
| DISPENSE_ACK_TIMEOUT | DISPENSE ACK 미수신 | COMM_ERROR 유지 |
| RESULT_TIMEOUT | DISPENSE ACK 후 XYR 미수신 | COMM_ERROR 유지 |
| NO_DROP_DETECTED | XYR의 R=0 | FAILED, 수동 완료 허용 |
| EMPTY_BLISTER_SLOT | XYR의 R=2 | 다음 슬롯 이동 안내 또는 마지막 슬롯 교체·복약 선택 |
| RESULT_COORD_MISMATCH | 결과 좌표가 대상과 다름 | 결과 무시, 로그와 관리자 점검 |
| DB-READ-ERROR | LCD 상태 DB 조회 실패 | 장치 오류 화면 |

## 13. 데이터 및 기록

- 예약: 약 이름, 예정 시각, 허용시간, 상태, 좌표
- MOVE: 요청번호, 최초 전송 시각, ACK 시각, WAIT 시각
- DISPENSE: 요청번호, 최초 전송 시각, ACK 시각, 결과 시각
- 결과: 상태, 완료 시각, 오류코드, 사용자 확인 시각
- 설정: 음성 반복 횟수, 볼륨 단계
- 장치: 다음 슬롯 좌표, 블리스터 소진 여부
- 이벤트: 예약·전송·ACK·WAIT·결과·설정·초기화 발생 시각

요청번호 시퀀스는 일정 삭제나 블리스터 초기화로 되돌리지 않는다.

## 14. 부팅 및 오프라인 정책

1. 부팅 시 `slotguard.service`가 Flask·DB·UART를 자동 실행한다.
2. LightDM 자동 로그인 후 X11에서 Chromium이 `/display`를 키오스크 모드로 연다.
3. Wi-Fi와 인터넷이 없어도 SQLite 예약, LCD, 음성, UART는 동작한다.
4. LCD와 인증 없는 상태 API에는 관리자 웹 주소와 로컬 IP를 노출하지 않는다.
5. Pi의 현재 시각이 부팅 기준으로 확인되지 않으면 예약과 UART를 차단한다.
6. 시스템 종료는 `systemctl poweroff`, 재시작은 `systemctl reboot`를 제한된 권한 도우미로 실행한다.

## 15. 시험 항목

- 10개 좌표의 MOVE→WAIT 전수 시험
- 지그재그 순서 `00→01→02→03→04→14→13→12→11→10` 표시·사용 상태 시험
- 10개 좌표의 DISPENSE 및 XYR 좌표 일치 시험
- MOVE/DISPENSE ACK 유실 시 10초 재전송 및 모터 중복 동작 없음
- ATmega 재부팅 후 같은 요청번호 재수신 시 중복 동작 없음
- R=0 후 수동 완료 시 한 번만 다음 슬롯 이동
- R=2 후 새 요청번호·남은 시간으로 다음 슬롯 MOVE, WAIT 후 약 배출 버튼 재표시
- 연속 R=2 후 R=1에서 DISPENSED 종료와 오류코드 해제
- R=2 재이동 뒤 R=0에서 기존 실패 화면과 좌표 유지
- INVALID_FORMAT 재전송 중 현재 진행 화면 유지
- 마지막 슬롯 R=2 교체 후 대형 좌우 수동복약·수동미복약 버튼
- 수동복약의 00→01과 수동미복약의 00 MOVE 재개·허용시간 만료 MISSED
- 중복 RESULT 수신 시 한 번만 슬롯 이동
- 같은 시각 일정 등록 거부
- 허용시간 기준이 예약 시각인지 확인
- Wi-Fi 단절 상태에서 예약·음성·UART 유지
- 10번째 슬롯 이후 신규 예약 차단과 LCD 초기화 후 복구
- 터치 모서리, 장갑, 스타일러스, 연속 탭 시험
- 종료·재시작·초기화 2초 길게 누름 시험
- 볼륨 0·1·5·10에서 표시와 1회 테스트 재생 시험
- 전원 재인가 후 설정·상태·요청번호 복구 시험

- Flask `/display`, `/api/display-status` 구현
